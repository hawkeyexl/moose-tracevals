**Scope:** getting a dependable gate into automation. Reading results downstream (JSON, history,
regressions) is covered in [Exit codes & reports](/tracevals/ci/exit-codes-and-reports/).
Deciding what the criteria assert is [Declare what to check](/tracevals/declare/).

The short version: **tracevals can run in a build with no network call and no API key.** That is
`--deterministic-only`, and it is a complete mode in its own right.

## First, where does the trace come from?

This is the question that decides your whole setup, so it comes before the recipe.

Agent sessions are written on the machine the agent ran on. A CI runner has no session store of its
own, so a trace has to get there. Three patterns work:

| Pattern | When it fits |
|---|---|
| **Evaluate in the same job that ran the agent** | An agent runs in CI and you evaluate its session immediately afterwards. Simplest, and the trace never leaves the runner. |
| **Upload the trace, evaluate in a later job** | The agent runs in one job or workflow; the session file is uploaded as an artifact and downloaded by the evaluating job. |
| **Evaluate a committed trace** | A small corpus of representative sessions lives in the repo and is re-evaluated whenever artifacts change — a regression suite for your instructions. |

The third is the one people underrate. If you commit a handful of traces, this gate answers a
genuinely useful question on every pull request: *does this edit to `CLAUDE.md` break a check that
used to pass?*

## Stay offline

Two flags cover every offline case:

- **`--deterministic-only`** makes no model call at all. Judged evals are reported as `skipped`
  instead of failed, so an artifact with only judged criteria does not turn your build red for
  having been skipped.
- **`--provider mock`** exercises the whole pipeline, judge path included, without a network call. Use it to smoke-test wiring, not to check adherence: it returns a canned verdict.

<Aside type="caution" title="If you do let the judge run in CI">
Set a ceiling with `judge.maxCostUsd` and provision the API key as a secret. Also check that your
model's pricing is known. A model the pricing table does not recognize is costed at zero, which
silently disables the budget you set. See
[configuration](/tracevals/reference/configuration/).
</Aside>

## Control the environment

Trace discovery reads a session store under a home directory. On a shared runner, pin it explicitly
instead of inheriting whatever the runner has:

```bash
TRACEVALS_HOME=./session-store npx tracevals run ./traces/session.jsonl
```

`TRACEVALS_HOME` overrides the home directory for **both** trace discovery and user-level artifact
lookup. A relative value resolves against the current working directory. This repository's own CI
uses it to make runs reproducible on every machine.

<Aside type="tip" title="Use relative paths in workflow steps">
On Windows runners, an absolute POSIX path like `/tmp/x` resolves differently in a shell than in
`node.exe`. If a step is touched by both, keep the paths relative.
</Aside>

## GitHub Actions

A gate that evaluates a committed trace corpus on every pull request:

```yaml title=".github/workflows/tracevals.yml"
name: Agent adherence

on:
  pull_request:
    paths:
      - ".claude/**"
      - "CLAUDE.md"
      - "AGENTS.md"
      - "traces/**"
  workflow_dispatch:

permissions:
  contents: read

jobs:
  adherence:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7

      - uses: actions/setup-node@v6
        with:
          node-version: 24

      - run: npm install --no-fund --no-audit

      # No network call, no API key. Judged evals are skipped, not failed.
      - name: Evaluate agent sessions
        run: |
          npx tracevals run traces/refactor-session.jsonl \
            --deterministic-only \
            --format markdown \
            --output tracevals-report.md

      # Runs whether or not the gate passed — a failing report is the one you
      # most want to keep.
      - name: Publish the report
        if: always()
        uses: actions/upload-artifact@v5
        with:
          name: tracevals-report
          path: tracevals-report.md
```

The gate is the exit code: the step fails when `run` exits non-zero, which is exactly when an eval
failed, errored, or needs review.

### Evaluating a session the same job just produced

If an agent runs earlier in the workflow, it writes its session under the runner's home directory
and you can discover it instead of naming a file:

```yaml
      - name: Evaluate the session that just ran
        run: |
          npx tracevals list --all-projects --limit 1 --json > traces.json
          npx tracevals run "$(node -p "require('./traces.json').traces[0].file")" \
            --deterministic-only
```

`list --json` emits `{ "traces": [...] }` sorted newest-first, so the first entry is the session
that just finished.

## Other CI platforms

There is no platform-specific behavior to account for. The contract is a command, an exit code, and
optionally a file. Any system that can run Node 24 and branch on an exit code works:

<Tabs>
  <TabItem label="GitLab CI">
    ```yaml title=".gitlab-ci.yml"
    agent-adherence:
      image: node:24
      script:
        - npm install --no-fund --no-audit
        - npx tracevals run traces/refactor-session.jsonl --deterministic-only
      artifacts:
        when: always
        paths:
          - tracevals-report.md
    ```
  </TabItem>
  <TabItem label="pre-commit">
    ```yaml title=".pre-commit-config.yaml"
    repos:
      - repo: local
        hooks:
          - id: tracevals
            name: agent adherence
            entry: npx tracevals run traces/refactor-session.jsonl --deterministic-only
            language: system
            pass_filenames: false
    ```
  </TabItem>
</Tabs>
