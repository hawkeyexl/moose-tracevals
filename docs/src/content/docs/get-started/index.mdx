**Scope:** installing moose-tracevals and getting a real, readable result from a session that already
happened. It stops once you trust the output. Making the checks say something specific is
[Declare what to check](/moose-tracevals/declare/); putting this in a pipeline is
[Run it in CI](/moose-tracevals/ci/).

Everything on this page runs **offline**, with no API key.

<Steps>

1. ### Install

   moose-tracevals needs **Node.js 24 or newer**.

   <Tabs>
     <TabItem label="Project dependency">
       ```bash
       npm install --save-dev moose-tracevals
       ```

       Then invoke it as `npx moose-tracevals`.
     </TabItem>
     <TabItem label="No install">
       ```bash
       npx moose-tracevals --version
       ```

       Nothing to add to your project first.
     </TabItem>
   </Tabs>

   <Aside type="tip" title="One name, both paths">
   The package and the `bin` it installs are both called `moose-tracevals`, and `npx` resolves by
   package name. `npx moose-tracevals` therefore reaches this CLI whether or not it is
   installed. With a local dependency npm prefers `node_modules/.bin`; without one it fetches the
   package.
   </Aside>

   {/* test {"testId":"get-started-install","description":"The CLI runs and reports a version."} */}
   {/* step {"description":"The installed binary responds to --version.","runShell":{"command":"moose-tracevals --version","exitCodes":[0]}} */}
   {/* test end */}

2. ### Find a session

   moose-tracevals evaluates a **trace**: a record of a session that already happened, sitting on disk.
   You do not instrument anything and you do not re-run any work.

   Claude Code writes one JSONL file per session under `~/.claude/projects/<project-slug>/`. To see
   what is evaluable:

   ```bash
   npx moose-tracevals list --all-projects --limit 5
   ```

   ```
     1. 2026-07-02 00:00  Write a README for this repo.
        C:\work\other-project · 22222222-2222-2222-2222-222222222222 · 1KB
        C:\...\.claude\projects\C--work-other-project\22222222-....jsonl
     2. 2026-07-01 00:00  Fix the crash in src/app.ts.
        C:\work\demo-project · 11111111-1111-1111-1111-111111111111 · 1KB
        C:\...\.claude\projects\C--work-demo-project\11111111-....jsonl
   ```

   Each entry shows the timestamp and first prompt, then the project and session id, then the file
   path you can pass to `run`. Drop `--all-projects` to scope to the current directory's project.

   {/* test {"testId":"get-started-list","description":"list discovers traces in the session store."} */}
   {/* step {"description":"Listing every project finds the fixture sessions and exits 0.","runShell":{"command":"moose-tracevals list --all-projects --limit 5","exitCodes":[0],"stdio":"demo-project"}} */}
   {/* test end */}

3. ### Run your first evaluation

   Start with the mode that makes no model call at all:

   ```bash
   npx moose-tracevals run <trace-file> --deterministic-only
   ```

   `--deterministic-only` runs every check that needs no inference call. That is the seven
   [deterministic graders](/moose-tracevals/reference/graders/) decidable from the trace alone, plus
   `command` evals and the `human` review queue. It **skips** AI-judged evals instead of failing
   them.

   To exercise the whole pipeline, including the judge, without a network call:

   ```bash
   npx moose-tracevals run <trace-file> --provider mock
   ```

   <Aside title="Two other things worth knowing early">
   - Run with no arguments in a terminal and you get an interactive picker instead of having to
     name a file.
   - The default judge provider is `claude-cli`, which uses your local Claude CLI's own
     authentication. There is no API key to provision before your first real judged run.
   </Aside>

4. ### Read the report

   A deterministic-only run against a project with one skill, one subagent, and two rules files
   looks like this:

   ```
   moose-tracevals — /path/to/session.jsonl
   claude-code · claude-opus-4-8 · 2 turn(s) · /work/demo-project

     SKIP   writing-toolkit:identify-ai-tells › adheres-to-artifact (implicit)
            artifact skipped via metadata.eval-skip
     PASS   fix-bug › used-read
     FAIL   fix-bug › forbidden-tool
            [error] tool Bash was used 1 time(s) but must not be
     PASS   fix-bug › no-force-push
     REVIEW fix-bug › refactor-preserved-intent
            awaiting human review
     SKIP   fix-bug › eval-5
            ai evals skipped (deterministic-only run)
     SKIP   doc-writer › adheres-to-artifact (implicit)
            ai evals skipped (deterministic-only run)
     SKIP   CLAUDE.md › adheres-to-artifact (implicit)
            ai evals skipped (deterministic-only run)
     SKIP   AGENTS.md › eval-1
            ai evals skipped (deterministic-only run)

   Artifact coverage
     ✓ skill: writing-toolkit:identify-ai-tells /path/to/plugins/.../SKILL.md
     ✓ skill: fix-bug                           /work/demo-project/.claude/skills/fix-bug/SKILL.md
     ○ agent: Explore                           built-in agent (no definition file)
     ✓ agent: doc-writer                        /work/demo-project/.claude/agents/doc-writer.md
     ✓ project-rules: project rules

   Warnings
     ! 1 unparseable JSONL line(s) were skipped

   9 eval(s): 2 pass, 1 fail, 0 error, 1 needs-review, 5 skipped
   ```

   Five things are worth naming, because the rest of the documentation assumes them:

   - An **artifact** is an instruction file the session used: a skill, an agent definition, or a
     project-rules file. Here: `fix-bug`, `doc-writer`, `CLAUDE.md`, `AGENTS.md`, and a plugin
     skill.
   - An **eval** is one named check declared on an artifact. `used-read` and `forbidden-tool`
     were declared in `fix-bug`'s frontmatter.
   - **The grader decides how a check is answered.** `used-read` reads the trace directly, and
     `no-force-push` runs a script over it. `refactor-preserved-intent` is `REVIEW` because it asks
     for a human, and the `SKIP`s are AI-judged evals, which `--deterministic-only` does not run.
   - **`adheres-to-artifact (implicit)`** is what you get for free. An artifact that declares no
     evals still gets one judged eval asking whether the session followed its instructions. A first
     run therefore says something before you have authored anything.
   - **Artifact coverage** is the honest answer to *what did you not check?* A `✓` resolved to a
     real file; a `○` did not. `Explore` is a built-in agent with no definition file anywhere, which
     is expected, and fine.

   The one failure is the point of the exercise. `fix-bug` declares that it is edit-only; the
   session ran a shell command; the finding names the tool and the count.

   {/* step {"description":"The run exits 1 because the fixture session violates a declared eval.","runShell":{"command":"moose-tracevals run test/fixtures/traces/claude-session.jsonl --project test/fixtures/project --deterministic-only","exitCodes":[1],"stdio":"tool Bash was used 1 time(s) but must not be"}} */}

   {/* test end */}

5. ### Check the exit code

   | Code | Meaning |
   |---|---|
   | `0` | every eval passed or was skipped |
   | `1` | something failed, errored, or needs review |
   | `2` | moose-tracevals itself could not run: bad usage, unreadable trace, unknown format |

   The distinction between `1` and `2` is the one to hold on to: `1` means the agent did something,
   `2` means the tool did. Full detail in
   [Exit codes & reports](/moose-tracevals/ci/exit-codes-and-reports/).

</Steps>
