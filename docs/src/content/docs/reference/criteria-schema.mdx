**Scope:** the exact shape of the `metadata.evals` block. How to decide what to put in it is
[Declare what to check](/moose-tracevals/declare/). Source of truth:
`schemas/artifact-evals-0.2.json`.

## Where the block goes

In the YAML frontmatter of any instruction artifact: a `SKILL.md`, an agent definition, or a
project-rules file:

```yaml
---
name: fix-bug
description: Fix a reported bug, reproducing it with a failing test first.
metadata:
  evals:
    criteria:
      - name: used-read
        assertion: The session read at least one source file before editing.
        grader: tool-usage
        options:
          tool: Read
          expect: used
      - Reproduce the bug with a failing test before applying the fix.
---
```

The block is **validated against a published JSON Schema**, and additional properties are rejected
at every level, so a misspelled field fails loudly instead of being ignored.

## `metadata.evals`

| Field | Type | Default | Description |
|---|---|---|---|
| `criteria` | array | — | The checks. Each item is a string or an object. |
| `skip` | boolean | `false` | Skip this artifact entirely. It is reported as `skipped`, not evaluated. |

## A criterion

Each entry in `criteria` is one of two forms.

### String form

```yaml
- Reproduce the bug with a failing test before applying the fix.
```

Shorthand for an LLM-judged assertion. It normalizes to:

| Field | Value |
|---|---|
| `name` | `criterion-<n>`, derived from position |
| `assertion` | the string |
| `grader` | `llm` |
| `type` | `regression` |
| `severity` | `error` |

Convenient, but the derived name shifts if you reorder the list. Use the object form for anything
you want to reference or track over time.

### Object form

`assertion` is the only required field.

| Field | Type | Default | Description |
|---|---|---|---|
| `name` | string | derived from position | Stable identifier. Must match `^[a-z0-9][a-z0-9-]*$` — lowercase kebab-case. |
| `assertion` | string | **required** | What must have held in the session. |
| `grader` | enum | `llm` | `llm`, `tool-usage`, `skill-invoked`, `file-access`, `turn-count`, `cost`, `regex`, `json-output`. `llm` uses the ensemble judge; everything else is deterministic. |
| `options` | object | — | Grader-specific options, validated by the grader itself. See the [grader reference](/moose-tracevals/reference/graders/). |
| `severity` | `error` \| `warning` \| `info` | `error` | Only `error` findings fail the eval. |
| `type` | `capability` \| `regression` | `regression` | Reported, never enforced. See below. |
| `evidence` | string | — | A hint telling the judge where in the session to look. Judged criteria only. |
| `examples` | object | — | `{ pass: [...], fail: [...] }` — anchor examples of passing and failing behavior for the judge. |

```yaml
- name: reproduces-before-fixing
  assertion: The session ran a failing test that reproduced the bug before editing any source file.
  grader: llm
  severity: error
  type: regression
  evidence: Look for a test command in the tool calls preceding the first Edit.
  examples:
    pass:
      - "Ran `npm test -- crash.test.ts`, saw it fail, then edited src/app.ts."
    fail:
      - "Edited src/app.ts at turn 2 with no preceding test run."
```

`evidence` and `examples` are prompt surface. They are given to the judge and measurably improve
verdict quality on assertions that are easy to misread. They have no effect on a deterministic
grader.

## `capability` vs `regression`

`type` separates two different reasons for a criterion to exist:

| Value | Meaning |
|---|---|
| `regression` | Protects behavior that already works. A failure is news. |
| `capability` | Probes the boundary of what the agent can do. It is **expected to fail sometimes**. |

Both are reported; **neither changes enforcement**. A failing `capability` criterion still fails its
eval and still contributes to a non-zero exit code.

That restraint is deliberate. A `capability` criterion that could not fail the build would just be a
comment; the value of the field is that reports and history can tell the two apart, so a failing
probe is never read as a regression. New criteria, including everything `fill` writes, default to
`regression`, the conservative choice.

## Published schema versions

The block's schema is a **published artifact** that ships with the package, so consumers can pin it.

| Version | `$id` | Difference |
|---|---|---|
| `0.2` | `.../schemas/artifact-evals-0.2.json` | Current. Adds `type`. |
| `0.1` | `.../schemas/artifact-evals-0.1.json` | Still shipped for pinned consumers. Identical apart from `type`. |

Both are importable from the package:

```js
import schema from "moose-tracevals/schemas/artifact-evals-0.2.json" with { type: "json" };
```

`0.1` → `0.2` is additive: every valid `0.1` block is a valid `0.2` block. A released version is
never edited in place; a change ships as the next version.

## The implicit eval

An artifact with **no** `criteria` still gets one judged eval, named `adheres-to-artifact`:

> The session adhered to the instructions in this `<type>` ("`<name>`"). Cite the specific
> instructions followed or violated.

The artifact's full text is given to the judge, capped at 8,000 characters. This is why a first run
produces meaningful output before you have authored anything.

Declaring any criterion replaces the implicit eval for that artifact. Once you start declaring,
declare what matters: the general check no longer runs alongside.

## When the block is invalid

A malformed block is **never silently ignored**. It produces an eval named `evals-block-valid` with
an `error` outcome, a JSON Pointer to the offending field, and a source line number:

```
  ERROR  fix-bug › evals-block-valid
         invalid metadata.evals block: /criteria/1/grader (line 12): must be equal to one of the allowed values
```

<Aside title="Only YAML frontmatter can be written">
`fill` writes to YAML frontmatter only. TOML (`+++`) and JSON (`;;;`) frontmatter are refused:
`only YAML frontmatter can be edited (found toml frontmatter)`. Reading and evaluating an existing
block is unaffected.
</Aside>
