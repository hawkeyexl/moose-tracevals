**Scope:** the export surface. How to *use* it is [Build on moose-tracevals](/moose-tracevals/extend/).
Source of truth: `src/index.ts`.

```ts
import { runEvals, parseTraceFile, registerGrader } from "moose-tracevals";
```

ESM-only, Node.js 24+, types shipped. **★ marks an intended entry point** — the rest is exported
because the CLI is built from it and it is useful for tests, but those are the ones to reach for
first.

## Subpath exports

| Specifier | What it is |
|---|---|
| `moose-tracevals` | The API below. |
| `moose-tracevals/schemas/artifact-evals-1.0.0-proposal.1.json` | The current evals-block schema. |

## Engine

| Export | Notes |
|---|---|
| ★ `runEvals(options)` | Runs the whole pipeline, returns `RunReport`. Needs a `judge` unless `deterministicOnly`. |
| `EngineOptions` | `tracePath`, `projectDir?`, `env?`, `config`, `judge?`, `deterministicOnly?`. |

## Commands

The CLI's three commands, callable directly. Each pairs a runner with a renderer.

| Export | Notes |
|---|---|
| `runRun`, `RunCommandOptions`, `RunCommandResult` | `run`. `RunCommandOptions.judge` injects a judge. |
| `runFill`, `renderFill`, `FillOptions`, `FillReport`, `FillArtifactResult`, `FillRun`, `FillStatus`, `SharpeningNote` | `fill`. `FillOptions.providerInstance` injects a provider. |
| `runList`, `renderList`, `ListOptions`, `ListRun` | `list`. |

## Judge

| Export | Notes |
|---|---|
| `makeTraceJudge(options)` | Build the ensemble judge. |
| `makeJudgeProvider(...)`, `providerSpecFor(...)` | Provider construction. `providerSpecFor` resolves identity without constructing, so a fully cached run needs no API key. |
| `renderTrace(trace, options?, plan?)` | The transcript as the judge sees it. With a `plan`, only that artifact's window. |
| `JUDGE_SYSTEM_PROMPT`, `buildUserContent(plan, rendered)` | The prompts. |
| `PROMPT_VERSION` | Cache-key component. Bump on any prompt change. |
| `cacheKey(...)`, `sha256(...)` | |
| `TraceJudge`, `JudgedEval`, `TraceJudgeOptions`, `RenderOptions`, `MockResponse` | |

<Aside type="caution" title="`TraceJudge` is the seam, not `makeTraceJudge`">
Anything matching the `TraceJudge` function type works, which is what makes downstream suites
offline-able. You rarely need `makeTraceJudge` unless you want the real ensemble.
</Aside>

## Configuration

| Export | Notes |
|---|---|
| ★ `loadConfig(dir?)` | Read `moose.config.yaml` from `dir`, take its `tracevals` section, validate, and fully populate defaults. |
| `parseConfig(raw)` | The same from an object. `raw` is the **section**, not the whole file — pass what sits under `tracevals:`. |
| `DEFAULT_CONFIG_FILENAME` | `"moose.config.yaml"` — the config file shared by the moose family. |
| `CONFIG_SECTION_KEY` | `"tracevals"` — the top-level key in that file holding this tool's settings. |
| `TracevalsConfig`, `ProviderConfig`, `Pricing` | |

Downstream code always receives a fully-populated config, so there is no need to re-apply defaults.

## Reporting and history

| Export | Notes |
|---|---|
| ★ `render(report, format)` | `"human"`, `"json"`, or `"markdown"`. |
| `ReportFormat` | |
| `appendHistory(file, report)`, `loadHistory(file)`, `compareToLast(...)`, `entryFor(report)` | |
| `HistoryEntry`, `HistoryEval`, `HistoryComparison` | |
| *(all of `types`)* | `TracevalsError`, `RunReport`, `EvalResult`, `RunSummary`, `Outcome`. |

`TracevalsError` is the operational-failure type. The CLI maps it to exit `2`; catch it if you want
to distinguish "the tool could not run" from "a check failed".

| Export | Notes |
|---|---|

| `ALLOWED_GRADERS` | Per-artifact-type grader allowlist. |
| `ProposedCriterion`, `Rejection`, `RejectionReason`, `Vocabulary` | |
| `PROPOSAL_SCHEMA`, `isValidProposal(...)` | The shape a proposal must match. |
| `systemPromptFor(type)`, `buildFillUser(...)` | |
| `FILL_PROMPT_VERSION`, `MAX_BODY_CHARS` | Cache-key components. |
| `FillCache`, `fillCacheKey`, `FillCacheKeyParts` | Separate from the judge cache. |
| `artifactFacts(...)`, `ArtifactFacts` | Grounding inputs, not evals. |
| `buildVocabulary(...)`, `BUILTIN_TOOLS` | |
| `mockFillProposal` | The canned proposal `--provider mock` returns. |

<Aside title="Stability">
The package is pre-1.0 and versioned by semantic-release from Conventional Commits. The ★ entry
points are the ones the CLI itself is built on and the least likely to move; the `fill` internals
exist mostly to serve this repository's own tests.
</Aside>
