**Scope:** the complete command-line surface. Source of truth: `src/cli.ts`.

```
moose-tracevals [options] [command]

Commands:
  run [options] [traces...]  Evaluate one or more traces against the skills and
                             instructions they used
  fill [options] [paths...]  Propose eval evals for skills, agent definitions, and
                             project rules, and write those above the confidence threshold
  list [options]             List discoverable traces (Claude Code session files)
  help [command]             display help for command

Options:
  -V, --version              output the version number
  -h, --help                 display help for command
```

`run` is the **default command**: `moose-tracevals <trace>` and `moose-tracevals run <trace>` are equivalent.

<Aside type="tip" title="Invoking the binary">
The **package** and the `bin` it installs are both named `moose-tracevals`. Every command below is
written as the bare `moose-tracevals`; prefix it with `npx` if the CLI is not on your `PATH`.
</Aside>

## `run`

```
moose-tracevals run [options] [traces...]
```

Evaluates one or more traces against the skills, agent definitions, and project-rules files each
session used. **Read-only**: it never modifies the traces or the artifacts it evaluates.

### Arguments

| Argument | Required | Description |
|---|---|---|
| `traces...` | no | Paths to trace files, evaluated in the order given. Omit them in an interactive terminal to get a picker, or select them with the flags below. |

Omitting `traces` **without** a TTY and without a selector produces an error instead of a prompt:

```
moose-tracevals: no trace given; pass a trace file or run `moose-tracevals list`
```

### Which report you get

One command, two report shapes. What decides is **how the traces were selected**, not how many came
back — so a script can be written against the shape before it runs:

| Invocation | Report |
|---|---|
| `run <trace>` | [`RunReport`](/moose-tracevals/reference/report-and-exit-codes/#--format-json) — one session |
| `run <a> <b> …` | [`BatchReport`](/moose-tracevals/reference/report-and-exit-codes/#batch-runs) — rates across sessions |
| `run --all-projects` / `--since` / `--limit` | `BatchReport`, **even when the selector matches exactly one trace** |

Naming traces *and* passing a selector is an error rather than a precedence rule — either answer
would silently discard something you asked for:

```
moose-tracevals: name traces or select them with --all-projects/--since/--limit, not both
```

A selector that matches nothing is **exit 2**, not a green run. An empty corpus and a clean corpus
are indistinguishable downstream, so the gate says so instead of passing:

```
moose-tracevals: no traces matched (--all-projects, --since 7d); run `moose-tracevals list` to see what the session store holds
```

### Options

| Flag | Argument | Default | Description |
|---|---|---|---|
| `--project` | `<dir>` | the trace's recorded `cwd` | Artifact-lookup root, **and** the discovery scope when a selector is used without `--all-projects`. |
| `--all-projects` | — | off | Evaluate traces from every project in the session store. |
| `--since` | `<duration>` | — | Keep only traces modified within the window: `30m`, `24h`, `7d`, `2w`. Anything else is exit 2. |
| `--limit` | `<n>` | unlimited | Maximum traces to evaluate, applied after newest-first sorting. |
| `--provider` | `<name>` | `provider.default` (`claude-cli`) | Judge provider: `claude-cli`, `anthropic`, `openai`, `mock`. |
| `--model` | `<model>` | the selected provider's configured model | Judge model override. |
| `--runs` | `<n>` | `judge.ensembleRuns` (`3`) | Ensemble runs per judged eval. |
| `--deterministic-only` | — | off | Skip judged evals entirely. They are reported as `skipped`, not failed. No model call is made. |
| `--no-cache` | — | cache on | Bypass the judge cache. |
| `--max-cost-usd` | `<usd>` | `judge.maxCostUsd` (unset) | Judge cost budget for the whole invocation, **shared across every trace in a batch** — not applied per trace. |
| `-f, --format` | `<format>` | `human` | `human`, `json`, or `markdown`. |
| `-o, --output` | `<file>` | — | Also write the rendered report to a file. |
| `--history` | — | off | Append to the history file and compare with the previous run for the same session. In a batch this is **one entry per trace**, since history is matched per session. |
| `--report-unused-artifacts` | — | `reportUnusedArtifacts` (`false`) | List every skill and agent the session was [offered and never used](/moose-tracevals/declare/coverage/#offered-used-and-never-on-the-menu), instead of only counting them. Never changes the exit code. |
| `--fail-on-needs-review` / `--no-fail-on-needs-review` | — | config | Override [`failOnNeedsReview`](/moose-tracevals/reference/configuration/). Pass neither and the config value stands. |
| `--require` | `<module>` | — | Load a grader plugin. **Repeatable**, and **added to** [`plugins`](/moose-tracevals/reference/configuration/#plugins) rather than replacing it. |

### Exit codes

| Code | Meaning |
|---|---|
| `0` | every eval passed or was skipped — in a batch, on **every** trace |
| `1` | any `fail` or `error` — and `needs-review`, unless `failOnNeedsReview: false`. In a batch, also any trace that could not be parsed |
| `2` | operational error: bad usage, an unreadable trace named on its own, unknown format, a selector that matched nothing, a bad `--since`, a grader plugin that will not load |

<Aside title="An unreadable trace inside a batch is an entry, not an abort">
Naming one bad trace on its own is exit 2. Naming it alongside good ones is different: it becomes a
report entry carrying its error, the other traces keep their verdicts, and the run exits 1. One
unreadable file in a corpus of fifty must not cost the other forty-nine.
</Aside>

## `fill`

```
moose-tracevals fill [options] [paths...]
```

Proposes eval evals for the instruction artifacts in a project and writes those that survive the
gate. **The only command that writes.** `run` never calls it.

### Arguments

| Argument | Required | Description |
|---|---|---|
| `paths...` | no | Specific files or directories to fill. Omit to scan `--project`. An explicit file path is taken at its word; an unrecognized filename is treated as project rules. |

A path that does not exist is an operational error:

```
moose-tracevals: no such file or directory: ./nope
```

### Options

| Flag | Argument | Default | Description |
|---|---|---|---|
| `--project` | `<dir>` | current directory | Project root to scan. |
| `--dry-run` | — | off | Report proposals without writing them. **Recommended first invocation.** |
| `--confidence` | `<n>` | `fill.confidenceThreshold` (`0.7`) | Minimum confidence to write, `0`–`1`. |
| `--max-evals` | `<n>` | `fill.maxEvalsPerArtifact` (`8`) | Maximum evals per artifact, **including existing ones**. |
| `--max-cost-usd` | `<usd>` | `fill.maxCostUsd` (unset) | Proposal cost budget. |
| `--no-cache` | — | cache on | Bypass the proposal cache. |
| `--provider` | `<name>` | `provider.default` | `claude-cli`, `anthropic`, `openai`, `mock`. |
| `--model` | `<model>` | the selected provider's configured model | Model override. |
| `--require` | `<module>` | — | Load a grader plugin, same semantics as on `run`. |
| `-f, --format` | `<format>` | `human` | `human` or `json`. Note: no `markdown` here. |

Numeric flags are range-checked before anything runs. Out of range, or not a number:

```
moose-tracevals: --confidence must be a number between 0 and 1, got 1.5
```

<Aside title="`--require` changes little here">
`fill` never proposes a custom grader kind — the per-artifact-type allowlist is fixed. Loading a
plugin matters only when it *replaces* a built-in, since the gate ground-checks proposals with the
registered grader's `validateOptions`. It is honoured so that a repository's config means the same
thing to every command.
</Aside>

### Exit codes

| Code | Meaning |
|---|---|
| `0` | every artifact was processed without error |
| `1` | any artifact result has status `error` |
| `2` | operational error: an out-of-range numeric flag, a missing path, a grader plugin that will not load |

<Aside title="What fill never does">
Existing evals are never modified; a name collision fails the run. Only the YAML frontmatter block
is rewritten; the body is byte-identical. Project rules (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`) are
proposed but **never written**. See [Fill in evals](/moose-tracevals/declare/fill/).
</Aside>

## `list`

```
moose-tracevals list [options]
```

Lists discoverable traces from the Claude Code session store, newest first. Always exits `0` on
success.

### Options

| Flag | Argument | Default | Description |
|---|---|---|---|
| `-p, --project` | `<dir>` | current directory | Scope to one project's sessions. |
| `-a, --all-projects` | — | off | Scan every project in the session store. |
| `-l, --limit` | `<n>` | unlimited | Maximum traces to list. |
| `--json` | — | off | Emit `{ "traces": [...] }` instead of a table. |

Each table entry is three lines: timestamp and first prompt, then project, session id, and size,
then the file path:

```
  1. 2026-07-02 00:00  Write a README for this repo.
     /work/other-project · 22222222-2222-2222-2222-222222222222 · 1KB
     /home/you/.claude/projects/-work-other-project/22222222-....jsonl
```

When nothing matches:

```
No traces found. Pass --all-projects to scan every project, or --project <dir> to scope to one.
```

### JSON shape

| Field | Type | Description |
|---|---|---|
| `file` | string | Absolute path — pass this to `run`. |
| `mtimeMs` | number | Modification time; the sort key, newest first. |
| `sizeBytes` | number | File size. |
| `sessionId` | string? | The session's id, when present in the file. |
| `project` | string? | The recorded working directory. |
| `firstPrompt` | string? | First non-sidechain user message, first line, capped at 200 characters. |

## Environment variables

| Variable | Effect |
|---|---|
| `MOOSE_TRACEVALS_HOME` | Overrides the home directory for **both** trace discovery and user-level artifact lookup. A relative value resolves against the current working directory. Use it to make a run reproducible on a shared runner. |
| `MOOSE_TRACEVALS_LIVE` | Contributor-only. Set to `1` to include the live judge smoke test in this repository's own suite. Has no effect on the CLI. |
