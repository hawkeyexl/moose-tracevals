**Scope:** where traces come from and what agentevals reads out of them. Source of truth:
`src/trace/` — `detect.ts`, `claude.ts`, `discover.ts`.

## Supported formats

Format is **sniffed from the content**, not the filename. agentevals scans lines until one
identifies the format:

| Format | Identified by | Produced by |
|---|---|---|
| `claude-session` | `parentUuid` or `sessionId` on a record | Claude Code session files, `~/.claude/projects/<slug>/*.jsonl` |
| `claude-stream` | `session_id` on a record | `claude -p --output-format stream-json` |

Both normalise into the same `Trace` model, so everything downstream is format-agnostic. The
`TraceSource` union is currently just `claude-code`; it is the seam for future adapters
([ADR 01003](https://github.com/hawkeyexl/agentevals/blob/main/adrs/01003-claude-code-traces-first-with-an-adapter-seam.md)).

Lines that parse but identify nothing — `{"type":"summary"}` and similar metadata — are skipped
rather than treated as an error, so a leading metadata record does not defeat detection.

### Detection errors

All exit `2`:

| Message | Cause |
|---|---|
| `trace is not JSONL (supported formats: …)` | The file is not line-delimited JSON at all. |
| `unrecognized trace format (supported formats: …)` | Parseable JSONL, but no record carried a recognised key. |
| `empty or unparseable trace file (supported formats: …)` | Nothing in the file parsed. |

## What is extracted

| Field | Source |
|---|---|
| `skillInvocations` | `Skill` tool calls (`input.skill`, `via: "skill-tool"`) **and** `<command-name>` injections in user text (`via: "command-injection"`, leading `/` stripped, `<command-args>` captured) |
| `agentSpawns` | the `Agent` tool's `input.subagent_type`, plus its `description` |
| `fileAccesses` | `Read` / `Write` / `Edit` `input.file_path`, mapped to op `read` / `write` / `edit` |
| `toolCalls` | every tool call, with a sidechain flag |
| `turnCount` | non-sidechain user prompts. The stream format overrides this with `result.num_turns` |
| `usage` | **stream-json only** — `result.total_cost_usd` and token counts |
| `assistantTexts`, `userMessages` | message text, used by the `regex` and `json-output` graders |

<Aside type="caution" title="Session files carry no cost data">
`usage.totalCostUsd` comes only from a stream-json `result` record. Claude Code session files do not
have it, which is why a [`cost` grader](/agentevals/reference/graders/#cost) skips rather than passes
against them.
</Aside>

Unparseable lines are tolerated and counted, surfacing as a warning rather than an error:

```
Warnings
  ! 1 unparseable JSONL line(s) were skipped
```

Session bookkeeping records are ignored outright: `queue-operation`, `attachment`, `last-prompt`,
`custom-title`, `summary`, `mode`, and `pr-link`.

## Discovery

`agentevals list` and the interactive picker scan the session store:

```
<home>/.claude/projects/<project-slug>/*.jsonl
```

Results are sorted by modification time, **newest first**, then truncated to `--limit`.

### The project slug

A project directory maps to a store directory by replacing every non-alphanumeric character with a
hyphen:

```
/work/demo-project   →  -work-demo-project
C:\work\demo-project →  C--work-demo-project
```

That is Claude Code's own rule, reproduced so `--project` can find the right directory. The helper
is exported as `slugFor()`.

### Listing entries

| Field | Notes |
|---|---|
| `file` | Absolute path — pass this to `run`. |
| `mtimeMs` | Modification time; the sort key. |
| `sizeBytes` | File size. |
| `sessionId` | From the file, when present. |
| `project` | The recorded working directory. |
| `firstPrompt` | First non-sidechain user message that does not start with `<command-`, first line only, capped at 200 characters. |

To keep listing fast, only the **first 256 KB** of each file is read for the summary. A session
whose opening prompt sits past that window shows no `firstPrompt`; it is still fully parsed by `run`.

## `AGENTEVALS_HOME`

Overrides the home directory for **both** trace discovery and user-level artifact lookup —
`~/.claude/skills/`, `~/.claude/agents/`, and the plugin store.

```bash
AGENTEVALS_HOME=./session-store npx agentevals list --all-projects
```

- A **relative** value resolves against the current working directory.
- Unset, it falls back to the OS home directory.

Use it to make a run reproducible on a shared CI runner instead of inheriting whatever home the
runner has. This repository's own CI sets `AGENTEVALS_HOME=test/fixtures/home` for exactly that
reason.

<Aside title="It does not affect project lookup">
Project-level artifacts — `.claude/skills/`, `.claude/agents/`, `CLAUDE.md` — are found relative to
the trace's recorded `cwd`, or to `--project` when you pass it. `AGENTEVALS_HOME` only moves the
*user* and *plugin* halves of the search.
</Aside>

## Naming a trace directly

`run` takes any path; it does not have to live in the session store.

```bash
npx agentevals run ./traces/refactor-session.jsonl --project ./my-repo
```

This is the pattern for committing a small corpus of representative sessions and re-evaluating them
whenever instructions change. Pair it with `--project`, because the recorded `cwd` will not exist on
the machine running the check.
